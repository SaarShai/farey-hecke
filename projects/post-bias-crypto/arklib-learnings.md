# ArkLib learnings for Post-Bias Cryptographic Framework (PBC)

Source: [Verified-zkEVM/ArkLib](https://github.com/Verified-zkEVM/ArkLib) @ `main`, Lean toolchain `leanprover/lean4:v4.29.0`, mathlib4 via `VCV-io` transitive, plus `CompPoly`, `doc-gen4`, and `checkdecls`.

## TL;DR

Three things PBC should copy from ArkLib:

1. **Two-monad probabilistic semantics.** Every "honest party / adversary / sampler" is an `OracleComp oSpec α` from VCV-io, executed against a `QueryImpl oSpec (StateT σ ProbComp)`. Security predicates are inequalities on `Pr[event | run]` with explicit `init : ProbComp σ` and `impl`. This is the exact shape we need for "rejection sampler preserves support, with bounded entropy loss". Mirror their `Reduction.completeness` / `Verifier.soundness` skeleton (`init, impl, relIn, relOut, error : ℝ≥0`).
2. **Quarantine unproved facts in named `Sorries.lean` files,** not scattered `sorry`s. ArkLib's CI gates on *new non-sorry warnings* under `ArkLib/Data/`; sorries are tolerated as known gaps and tracked, not silently accumulated. This is the "external assumption boundary" we promised in WP3.
3. **Composition is a separate file with one theorem per security notion,** keyed off the same `init, impl` parameters. `Reduction.append_completeness`, `append_soundness`, `append_knowledgeSoundness`, `append_rbrSoundness`, etc. all carry error-addition explicitly. PBC's "rejection sampling preserves support containment" + "avoid-list soundness composes" should be modeled the same way.

## 2. Probabilistic semantics via VCV-io

The single most transferable pattern. ArkLib never works with raw `PMF` for protocol semantics; everything is an `OracleComp oSpec α` interpreted by a `QueryImpl`.

Key incantation, from [`OracleReduction/Security/Basic.lean:32-93`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Security/Basic.lean):

```lean
variable {ι : Type} {oSpec : OracleSpec ι}
  {σ : Type} (init : ProbComp σ)
  (impl : QueryImpl oSpec (StateT σ ProbComp))

def completeness (relIn relOut) (reduction) (completenessError : ℝ≥0) : Prop :=
  ∀ stmtIn witIn, (stmtIn, witIn) ∈ relIn →
    let pImpl := QueryImpl.addLift impl challengeQueryImpl
    Pr[fun ⟨⟨_, (prvStmtOut, witOut)⟩, stmtOut⟩ =>
        ((stmtOut, witOut) ∈ relOut ∧ prvStmtOut = stmtOut)
       | OptionT.mk do
         (simulateQ pImpl (reduction.run stmtIn witIn).run).run' (← init)]
      ≥ 1 - completenessError
```

Pieces to mirror:

- **`OracleSpec ι`** — declarative spec of what oracles exist; the program is parametric in it. For us, an RSA sampler's `oSpec` lists "uniform bits", "primality oracle (modeled)", and "compromised oracle (in attack model)".
- **`OracleComp oSpec α`** — free monad. Use VCVio's `Pr_{...}[...]` notation (see [`Data/Probability/Notation.lean`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/Data/Probability/Notation.lean)) so spec statements read like math.
- **`QueryImpl oSpec (StateT σ ProbComp)`** — an interpretation into a stateful probabilistic computation. `σ` is the realized state (e.g., the entropy pool, the cached residue accounting). `init : ProbComp σ` samples the initial state.
- **`simulateQ pImpl program`** runs the program against the impl. The result is in `ProbComp`, on which `Pr[event | ...]` is defined.
- **Adversary = a `Prover`-shaped structure** ([`OracleReduction/Basic.lean:218-225`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Basic.lean)) with its own private state evolution: typeclass fields `sendMessage`, `receiveChallenge` are themselves `OracleComp`s. For us, an "adversary observing samples" is just a `QueryImpl` wrapper that logs.

`SampleableType` / `VCVCompatible` in [`OracleReduction/Prelude.lean:31-58`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Prelude.lean) is their typeclass for "this finite type can be uniformly sampled". `ZMod N` already inherits the relevant instances; PBC residue domains drop in directly.

## 3. The "external assumption" boundary

ArkLib does not use `axiom` for cryptographic hardness. The pattern is:

1. **`opaque def`** for noncomputable assumed-existing operations (decoders, solvers). Example: [`ArkLib/Data/CodingTheory/GuruswamiSudan/GuruswamiSudan.lean:60`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/Data/CodingTheory/GuruswamiSudan/GuruswamiSudan.lean):
   ```lean
   opaque decoder (k r D e : ℕ) (ωs : Fin n ↪ F) (f : Fin n → F) : List F[X] := sorry
   ```
2. **Dedicated `Sorries.lean` files** quarantine the unproved lemmas a module relies on. See [`ArkLib/Data/CodingTheory/BerlekampWelch/Sorries.lean`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/Data/CodingTheory/BerlekampWelch/Sorries.lean) — its docstring is literally "All the sorries Berlekamp-Welch decoder relies upon." Downstream files `import` it. This makes the assumption surface auditable from one file.
3. **`structure` with field-level `Error : ℝ≥0`.** Security is parameterized by an explicit error, not folded into a hardness assumption. Composition theorems show how errors add. See `IsComplete.completenessError`, `IsSound.soundnessError` — and the `class` typeclass wrapper so downstream code can synthesize.
4. **`init, impl` are external inputs.** They are *not* defined inside the kernel; they are arguments. This makes the boundary syntactic: anything below `init` and `impl` is internal; the choice of CSPRNG / oracle realization is external.

For PBC: put `CSPRNGUniformity`, `PrimalityOracleSoundness`, `FactoringHard` each as their own `Sorries.lean` (or `Assumptions.lean`) module with explicit statements and a short prose docstring. The kernel imports them but proves no theorems about them.

## 4. Finite-field / residue / modular-arithmetic patterns

Less directly reusable than I hoped — ArkLib mostly works over abstract `[Field F] [Fintype F]` for finite fields, leaning on mathlib's `Polynomial`, `Matrix`, `MvPolynomial` infrastructure. Specific patterns we *can* use:

- **`VCVCompatible` typeclass** = `Fintype + Inhabited + DecidableEq` ([`Prelude.lean:33`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Prelude.lean)). Every PBC residue domain `ZMod N` (for `N ≥ 1`) gets this for free via mathlib. Bundle it.
- **`Set.language` and predicate-as-`Set`** ([`Prelude.lean:107-118`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Prelude.lean)): relations are `Set (α × β)`, languages are `Set.image Prod.fst`. Mirror this for "allowed residue classes" as `Set (ZMod N)` and "support of sampler" as `Set α`. Support containment is then literal `⊆`.
- **No special simp set** for modular arithmetic; they rely on mathlib's `decide` / `omega` / `Fin.cast` machinery. PBC should follow suit, only adding a local `@[simp]` set if a benchmark shows it's worth it.

## 5. Composition lemmas

The pattern to copy verbatim. In [`OracleReduction/Composition/Sequential/Append.lean`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Composition/Sequential/Append.lean):

```lean
theorem append_completeness
    (R₁ : Reduction oSpec Stmt₁ Wit₁ Stmt₂ Wit₂ pSpec₁)
    (R₂ : Reduction oSpec Stmt₂ Wit₂ Stmt₃ Wit₃ pSpec₂)
    {ε₁ ε₂ : ℝ≥0}
    (h₁ : R₁.completeness init impl rel₁ rel₂ ε₁)
    (h₂ : R₂.completeness init impl rel₂ rel₃ ε₂) :
      (R₁.append R₂).completeness init impl rel₁ rel₃ (ε₁ + ε₂) := ...
```

Shape: `compose₁ ε₁ → compose₂ ε₂ → composed (ε₁ + ε₂)`. Same shape for soundness, knowledge soundness, rbr soundness, rbr knowledge soundness — one theorem each, all in the same file. They also prove monotonicity helpers (e.g., [`completeness_error_mono`, `completeness_relIn_mono`, `completeness_relOut_mono`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Security/Basic.lean#L122-L149)) which make `grind`/`simp` discharge subset / weaker-error obligations automatically.

For PBC: model "rejection sampling preserves support ⊆ allowed-class" as the analog of `append_soundness`. The "avoid-list bias bound after k rounds" is a monotonicity + error-addition lemma in exactly this shape. Add `@[grind]` / `@[simp]` to the monotonicity lemmas so users get them free.

Honest caveat: several of these theorems in ArkLib are themselves `sorry` (the type signatures are settled, the proofs are not). That's an instance of the "Sorries quarantine" pattern at the security layer — *the contract is fixed*, the proof is gappy.

## 6. "No-sorry" hygiene

This is the most directly stealable engineering payload. From [`scripts/validate.sh`](https://github.com/Verified-zkEVM/ArkLib/blob/main/scripts/validate.sh):

```bash
lake build 2>&1 | tee "$build_log"
python3 ./scripts/check-warning-log.py "$build_log" \
  --path-prefix ArkLib/Data/ \
  --exclude-substring 'declaration uses `sorry`' \
  --label 'ArkLib/Data non-sorry warnings'
./scripts/check-imports.sh
python3 ./scripts/check-docs-integrity.py
python3 ./scripts/kb/check_generated.py
python3 ./scripts/kb/lint.py --strict-cited-pages
```

Translation: the CI gate is "**no new non-sorry warnings**", scoped to `ArkLib/Data/`. Sorries are visible (the Lean compiler emits a warning per `sorry`) but tolerated. New unhygiene — unused vars, broken docstrings, missing imports — fails the build. The umbrella import is also checked (`check-imports.sh`).

CI ([`.github/workflows/ci.yml`](https://github.com/Verified-zkEVM/ArkLib/blob/main/.github/workflows/ci.yml)) additionally runs build-timing snapshots and posts deltas as PR comments — overkill for PBC at the start but useful once kernel size grows.

**For PBC's stronger promise ("no-sorry core"):** invert the policy. Run `grep -rn 'sorry' PBC/Kernel/` in CI and fail on any hit, while permitting sorries in `PBC/Kernel/Sorries.lean` (the assumptions module — itself listed explicitly in the certificate). The Lean way is `#print axioms theorem_name` per top-level theorem to confirm only whitelisted assumptions are used; run this as a CI script that diffs against an `expected_axioms.txt`. That is the "plain-English certificate" mechanism.

Also worth adopting: `scripts/kb/` is a directory of knowledge-base generators that produces a theorem index. The KB lint enforces "cited pages exist". For our certificate, the analog is "the `support-containment` theorem cited in the spec exists, type-checks, and depends only on whitelisted axioms".

## 7. Things to NOT copy

- **The full `ProverState`/`ProverInteraction`/`ProverInteractionWithOutput` zoo** ([`Basic.lean:128-225`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Basic.lean)). They are mid-refactor (literal TODOs in the file: "the current prover definition is too rigid..."). For PBC, an adversary is just `OracleComp oSpec α` with a witness output; do not build a structure hierarchy until you have a second concrete sampler that breaks the abstraction.
- **`OracleVerifier.embed + hEq` for output-oracle subset specification** ([`Basic.lean:295-307`](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Basic.lean)). This bundles a `↪` embedding with a heterogeneous-equality proof obligation; the file itself flags this as awkward and pending a `simOStmt`-style replacement. We have no oracle-output story; skip entirely.
- **Universe polymorphism in core defs.** ArkLib mixes `Type u, Type v` and pays for it in elaboration errors and commented-out instances. PBC's residue domains live in `Type`; pin to `Type 0` until you have a concrete reason not to.
- **Build-timing CI** until the kernel is >5 files. Premature.
- **Blueprint LaTeX infrastructure** (`blueprint/`, `home_page/`, `docs/wiki/` generators) until the kernel stabilizes. The blueprint pipeline is heavy and dual-maintained. The PBC certificate doc can start as plain markdown.
- **`autoImplicit = false` globally** is correct, but they also accept long argument lists in `variable` blocks that span 8 lines (see [Security/Basic.lean:32-39](https://github.com/Verified-zkEVM/ArkLib/blob/main/ArkLib/OracleReduction/Security/Basic.lean#L32)). Mimic the convention but consider grouping into a `section` per concept rather than one global variable block.
