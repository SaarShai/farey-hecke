# GOAL — FunSearch/AlphaEvolve-mode target: scope a beatable, verifiable extremal-construction problem, then pilot

Date 2026-06-27. The honest reframe: our one differentiated, UN-owned edge is the fleet of
parallel REASONING agents + adversarial falsification + exact/interval-certified verification =
the FunSearch (Nature 2024) / AlphaEvolve (DeepMind 2025) evolutionary-construction paradigm.
It produces REAL new math (a record / witness / settled case is a genuine contribution), is
unsaturated, and yields trivially-checkable concrete objects.

## CRITICAL constraint — we are SAMPLE-LIMITED, not DeepMind
FunSearch/AlphaEvolve ran millions of evaluations in a tight inner loop on big compute. We run
DOZENS-to-low-HUNDREDS of agent proposals. So we MUST target the NEGLECTED LONG TAIL, not the
famous records DeepMind already swept. Our realistic wins:
- the object is SMALL + exactly verifiable (a few hundred smart proposals can find a record), OR
- STRUCTURE/REASONING is the bottleneck (LLM-proposal beats random/FLOPS search), OR
- the current record came from a WEAK / non-exhaustive method and a fresh idea beats it.

## HARD FILTER (ALL must hold)
1. FINITE object, EXACTLY + INDEPENDENTLY verifiable (a witness anyone can check).
2. Beatable by SAMPLE-LIMITED smart search (small object / structure-bottleneck / weak current method).
   NOT raw-FLOPS-bound.
3. NOT owned/saturated. Web-verify it is NOT already in: FunSearch (cap sets, admissible sets, online
   bin packing, Erdős min-overlap), AlphaEvolve (~50+ bounds: matrix mult, packing, autocorrelation,
   many Erdős problems), or a specialist-cultivated table (Packomania, Brouwer/Grassl code tables,
   Radziszowski Ramsey survey, erdosproblems.com solved list) — UNLESS a genuinely open small case remains.
4. SIGNIFICANCE: the community would recognize the record/witness/settled-case as a real (if modest)
   contribution.
5. AVOID: analysis-bound (circle-method / spectral-gap / minor-arc); Hecke/Maass/QUE/arithmeticity
   (owned-for-us).

## Domains (one survey agent each — cast wide, hunt the long tail)
A. OEIS extremal / "hard" sequences — next-term-is-a-finite-construction, few terms known, neglected.
B. erdosproblems.com — OPEN, construction/computation-tractable; brutal novelty vs AlphaEvolve sweep.
C. Combinatorial & discrete geometry — neglected packing/covering, no-3-in-line, Heilbronn-type,
   distinct-distances / optimal point configs.
D. Coding / design theory / finite geometry — open small cases in code / covering-code / design /
   cap / arc tables.
E. Extremal graph/hypergraph & Ramsey/Turán — CONSTRUCTION-side lower-bound records NOT owned by SAT
   solvers (avoid Heule/SAT turf).
F. Recently-posed (2023-2026) extremal/optimization problems, niche, no specialist sweep yet.

## Each agent: SURVEY then adversarial VERIFY
SURVEY: 3-5 candidates; each = precise statement | current record + web-verified source (who/when) |
why sample-limited-friendly | what a concrete verifiable contribution is | novelty/owned status (brutal).
Rank. VERIFY: try to KILL your top pick — secretly owned? secretly FLOPS-bound? not actually open?
not verifiable? Be adversarial.

## Rules (every agent; hooks don't fire in subagents)
READY FOR JUDGING not "done". NEVER fabricate a record or citation — web-verify or mark UNVERIFIED.
KNOWN vs CLAIMED. Concrete (named problems, people, dates, numbers). Write ONLY your assigned file. No git.

## Synthesis (main loop)
Rank all by (realistic-shot-at-a-record × not-owned × exactly-verifiable × significance). Pick THE one
(or 2). Then run a PILOT evolutionary construction-search on it: proposer agents emit candidate objects
as code/data → exact evaluator scores → keep best → mutate/iterate → independently verify any record.
