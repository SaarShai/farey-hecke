## What was wired & why this route (honesty)

The task named `BCZHeckeUniformOnset.per_q_Xomega_lb_{4,5,6}win`. Those theorems demand a
3rd hypothesis `hOrbitData` (per-orbit trichotomy + deep-mid ejection in
`Pgen`/orbit shape). **No verified lemma produces `hOrbitData`** as stated:
`HeckeS1.step_trichotomy` gives a per-point `branchIdx` classification (not the
orbit-shaped `Dcorr`/`Tmap`/cusp-guard disjunction), and
`HeckeEjectionUniform.ejection_kick_uniform` is a pure-`(l,r,u,v,thr)` algebra lemma
valid only on the q≥16 box `l∈[49/25,2]` — neither is in the `hOrbitData` form, and an
adapter producing it does not exist as verified code.

Instead the wiring uses the **already-blessed UNCONDITIONAL route** from
`BCZHeckeXOmega_corridor_q18_UNCONDITIONAL.lean` (`HeckeGenuine.perq_essSup_ge`), which
needs only the F-window + minpoly + band + measure setup — and **no trichotomy/ejection**,
because on `Dcorr` every `Tmap`-orbit step is scalar by construction (the `Dcorr`
membership hypothesis carries it; cusp/deep-mid cannot occur, so they are vacuous for
q ≤ 18, confirming the task's "deep-mid may be vacuous" note). This is exactly the
pattern `Xomega_corridor_lb_q18` already used and that is recorded as UNCONDITIONAL.
The engine (`essSup_ge_of_no_sustained_strict`, `Tmap`, `Pprod`, `Dcorr`,
`orbit_to_cseq_hyps`) was **inlined verbatim** (axiom-checked) into namespace `UQ`
because the corridor file *also* defines a top-level `g18_no_window_below_genuine` that
clashes with `BCZHeckeG18_window_VERIFIED` — so it cannot be imported alongside the q=18
window file. The 14 window `_VERIFIED` files are **imported (not edited)** as a Lake lib.

Window-size grouping: `FwindowHyp4/5/6` differ only in conjunct count (4/5/6). A 4- or
5-window refutation feeds the engine's first 4/5 sub-threshold products; the per-q
adapter `hF{q}` is a thin η-expansion of `g{q}_no_window_below_genuine`, dropping the
unused `hlo` for q∈{5,7,8,9,12,15} and threading it for the rest.

The measure hypotheses (μ invariant prob on `Dcorr`, `Pprod` a.e. ≤ M) are carried as
hypotheses — the standard ergodic-optimization setup, identical to the blessed q=18
